# Changelog

## 1.7.4

- I fixed the Settings window on Windows. Some rows (Game library folders, Max download size, Auto-convert ISOs) squeezed their text to about one word per line. Settings is wider now, and long rows put the control under their text.
- I fixed extracting to FAT32 drives. 1.7.0 refused any archive over 4 GB, even though FAT32's limit is per file. Now I only refuse a single file of 4 GB or more, and I name that file. A game ISO over 4 GB with Auto ISO → GOD (or XEX) on is extracted to a temporary folder on your PC's drive, converted straight onto the FAT32 drive, and the temporary copy is deleted afterwards, even if the convert fails or you cancel. Your PC's drive needs room for everything in the archive (not just the ISO) plus 256 MiB while that happens. Other game files in the archive land next to the `Content` folder, the same as a normal extract.
- When you extract to a `Content` folder, I now skip extras that aren't needed on the console (readme `.txt`, `.nfo`, `.url`, pictures and the like) that sit beside the ISO, instead of leaving them in a folder at the drive root, and the summary lists what I skipped. I never touch anything inside a game or app folder (one with a `.xex` or any other real file), so its pictures, text files and web UI stay.
- I fixed `.unpack-replace.lock` being left in the game's type folder (for example `5454081A\00007000`) after a GOD convert or Replace on Windows. I now delete it when the job is done, and a leftover one from an older version or a crash is cleaned up the next time I write to that folder.
- I fixed the Library. In 1.7.0, pointing it at a profile folder like `D:\Content\0000000000000000` could show "No games found yet" (an old empty index was reused for up to an hour, and Refresh didn't rescan), and pointing it at `D:\Content` or a whole drive could spin forever. The scan is now bounded (it no longer walks every file inside each game's `.data` folders or every folder on a drive), Refresh always rescans, and the spinner shows progress with a Cancel button and gives up after 10 minutes. The drive root (`D:\`), `D:\Content`, any profile folder and a single TitleID folder all work as a library folder.
- I fixed Library game counts and types. The scan now lists GOD (`00007000`), installed disc (`00004000`), XBLA (`000D0000`, name from the STFS header), original Xbox (`00005000`), and optional apps (`00040000`), and it skips save-only profiles, avatar-only folders, DLC-only and TU-only TitleIDs. DLC and TU badges use `00000002` and `000B0000` respectively (empty `000B0000` means no TU).
- I fixed Library cover art. The index no longer downloads covers during a scan (so the list shows right away and a cached index still works). With “Library cover art from the internet” on, covers load in the background a few at a time from XboxUnity over HTTPS, are downscaled to a small JPEG, cached under app data with atomic writes, and failed lookups are not retried for several hours until you hit Refresh. Turning the setting off stops new downloads. When a cover loads, the initials tile hides. If a library folder no longer has file access, I show a hint and a **Grant access** button in Settings (native folder picker).
- I fixed folder access security. Folders you pick in native dialogs are remembered in app data (separate from settings) and I restore file access for them automatically on startup. Importing settings cannot add to that list. The old page command that granted arbitrary paths is gone. On first launch after 1.7.4 I show a one-time native confirm for your existing saved library folders; after you agree, those folders stay automatic like any other pick. I refuse system locations (Windows and Unix system folders, `AppData`, device paths, UNC shares, and the system drive root like `C:\` or `/`) but normal profile folders such as Downloads, Documents, Desktop and Public work. A USB drive root you picked with the dialog is restored on startup; the system drive root is not. When you add a drive or `Content` folder from **Scan drives**, I record that choice the same way as a dialog pick. Picking the system drive root in the dialog is refused with a clear message.
- I fixed **Replace files** repair (K1): repair no longer treats a truncated live `.data` as finished after an interrupted cross-volume copy unless the note recorded that half as moved in; if you edit the new `.data` after the new header is in place and the note says that half finished moving, I keep the header and your edits and only remove old aside copies that still match their fingerprints.
- I fixed **Replace files** during a folder move (K2): at lock time I record the type folder's identity (device and inode on Unix, volume serial and file index on Windows, including directory paths under Content); if you rename or move that folder mid-job, I stop, roll back only what I can prove is mine, and explain what happened.
- I moved inline `style=` attributes in my HTML strings into CSS classes and removed Tauri's `dangerousDisableAssetCspModification` entry for `style-src`.
