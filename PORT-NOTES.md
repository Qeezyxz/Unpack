# Port notes: v1.6.0 merge

Base: the reviewed Unpack source (`527083b`, 14 review rounds), imported unchanged as the first commit of this branch.
Source of the additions: the history of `main` (v1.5.0, 35 commits, listed below). Nothing in the base was removed: no feature, no safety check (path grants, no writes through links, `.partial`/`.part` + verify, atomic `claim_dir`, ISO tokens, FTP LAN-only rules, SSRF-hardened downloads, signed catalog, strict CSP, "network only from Rust, only on click"). The 222 Rust tests and every UI suite of the base still pass.

Main is a rewrite made from fragments (`commands.rs`, `xbox.rs`, `usb.rs`, `convert.rs`, `fileops.rs`, one big `styles.css`). Its features were re-implemented inside the base's modules, not copied over them.

## Not ported as written, and why

- **Unknown TitleID hard stop.** Main stops the convert with "Title ID XXXXXXXX not recognized". That blocks valid conversions (homebrew, betas, region variants not in the list), so it is a warning that names the hex ID and still converts, as requested. Folder naming falls back to the file name or the title typed by the user.
- **Main's UI shell** (`styles.css`, the settings modal, `logo.png`, the window size, `mainBinaryName`, dark default theme): not adopted. The base UI, assets and its System/Light/Dark theme (default System) are kept. Main's "restore original UI / mark" commits (`4be187d`, `5546fbc`) do not differ in a way that matters: the base icon is the same isometric box and up-chevron (a larger render of the same mark), so no asset was replaced. `tests/theme.test.mjs` is adapted to the base default (no stored value → follows the system).
- **`fileops.rs`, `commands.rs`, `xbox.rs`, `usb.rs`, `convert.rs`, `paths.rs`:** not copied; their behavior exists in the base modules (see the safer-writes row). Main's "skip `launch.ini` unless you opt in" is covered differently: nothing is ever overwritten on the console or the USB drive, and the catalog installer handles `launch.ini` with a backup, rollback and restore (both have tests above).
- **Auto-retry loop and "no progress after N tries" message** of main's Send to Xbox: the base has no automatic retry (a drop stops the send and **Resume** continues from the `.part`), so there is nothing to count; the full-drive and drop messages are ported, the stall counter is not.
- **Discord in the browser/web build:** the page only calls Discord commands inside the desktop app.
- **Per-destination locks on `dlc_install` and `extract_entry`:** not added. DLC install creates its target with `create_new` (race-safe by itself) and a single-file save replaces atomically; FTP already has the app-wide `FTP_BUSY` lock.
- **ISO auto-convert chain stays serial** (one convert at a time, app-wide). That is what makes Disc 1 and Disc 2 from one archive land in one folder deterministically; "jobs at once" governs extractions.
- **`sample.rar`** in the test data is a small synthetic RAR4 written by `tests/make_testdata.py` (no RAR encoder is available on Linux); the base's other fixtures are built with 7-Zip.
- **Windows-only pieces not built here:** the NSIS installer, and the Windows CI jobs could not be run on this Linux VM. `Unpack-Cleanup.exe` was cross-compiled with MinGW on Linux using the workflow's exact flags, but never executed. `cleanup.c`'s logic changed (it loops over both the new and the old identifier).
- **No release, no tag, no merge:** the release workflow is manual and publishes nothing.

## Behaviour changes worth a reviewer's attention

- The app identifier changed (`com.justin.unpack` → `com.qeezyxz.unpack`), so app data (grants, FTP resume records, catalog state) starts fresh for anyone who ran an earlier build; `localStorage` settings do too. Revert that one line if continuity matters more than matching main.
- `ftp.rs` `stor` now waits up to 3 s for a reply after a failed write (to tell "full" from "dropped") before returning the error.
- A rejected `iso_companions` call (folder not granted) is silently ignored by the page; nothing is offered.
